# フライトプラン作成の手順を短くする

## メタデータ

- **Status**: Done
- **Date**: 2026-10-17
- **親**: [20260308-flight-plan-setup-page](../20260308-flight-plan-setup-page/spec.md)

## 概要

`/flight-plan-setup` で、空の状態から 1 機を置く手順を「コールサイン・出発・到着」に縮める。経路は追加と同時に提案し、フィックスの削除と並べ替えは一覧で行い、地図の操作はプレビュー上に常時示す。

## 背景・課題

### 現状

- 追加フォームは緯度・経度・高度・針路・地速・昇降率の手入力を要求し、経路は空のまま登録される。
- 経路テキストの修正は Apply を押すまで反映されない。Suggest と ATS 選択は即時反映である。
- 地図のクリック追加・区間挿入・Now のドラッグは README にのみ書かれている。
- `GET /ats/airports` は ICAO と座標のみを返す。`airports.json` の名称と IATA は API に出ていない。

### 課題（Problem Statement）

- 1 本の経路を作るために、ICAO の暗記と緯度経度の手入力が先に来る。
- 経路の途中を抜く・順番を変える操作がカンマ区切り文字列に寄っている。
- 地図が編集の本体なのに、使える操作が画面上で分からない。

### なぜ今か（Motivation）

テンプレート 28 機と JSON 入出力は既にある。次に訓練シナリオを増やすときのボトルネックは、空の状態からの 1 機作成である。

---

## 方針

### 決定方針（Decision）

1. 追加入力はコールサイン、出発空港、到着空港とする。空港は `GET /ats/airports` の候補から選ぶ。
2. 追加直後に経路を提案する。初期緯度・経度は出発空港とする。高度・針路・速度の初期値は既存の巡航既定（31,000 ft / 90° / 450 kt / 昇降率 0）のまま、地図下の初期位置編集で直す。
3. 選択機の巡航フィックスは番号付き一覧にする。削除、一つ前、一つ後、ドラッグ並べ替えは即時にシナリオへ書く。カンマ区切りの Apply は選択機エディタから外す。
4. ルートプレビューの見出し下に、フィックスクリックで末尾追加、緑の区間クリックで挿入、Now ドラッグで初期位置、という操作を常時表示する。
5. 画面は管制コンソールの暗い列をやめ、左を生成り色の計画ストリップ、右を角丸のチャートにする。テンプレート、JSON、同じ出発・到着への一括上書きはストリップ内に残す。

### 検討した他案（Alternatives Considered）

- **案 A: 画面全体の視覚テーマを作り直す。** 手順の長さは残るため却下。
- **案 B: 公示 SID／STAR を同時に導入する。** 手続きデータの範囲が別問題のため却下。
- **案 C: 初期位置を提案経路の先頭フィックスにする。** 出発空港の方が「どこから置くか」が説明しやすい。先頭フィックスへの移動は地図ドラッグで足りる。

### トレードオフ（Trade-offs）

- **メリット**: 空の状態から 1 機を、空港名の選択と提案経路で置ける。
- **デメリット / 受容する制約**: 提案が失敗した機は経路なしで残る。一括 O/D はテキスト適用のままである。追加直後の高度は地上ではなく巡航既定のままである。
